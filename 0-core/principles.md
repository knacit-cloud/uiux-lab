# 原則 — 人間の認知にどう合わせるか

デザインの「良し悪し」は好みではなく、**人間の認知の制約に合っているか**で決まる部分が大きい。
ここはその制約の一覧。個別のパターンに迷ったとき、ここに戻って判断する。

---

## Nielsen の10ヒューリスティクス

1994年に提唱され、今も UI 評価の標準として使われている10項目。
⚠️ 出典：[NN/g — 10 Usability Heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/)（本文照合済）

### 1. システム状態の可視性
今何が起きているかを、適切なフィードバックで常に伝える。
→ 読み込み中・保存済み・送信完了・エラー。**「押したけど何も起きない」を作らない。**

### 2. 現実世界との一致
ユーザーの言葉で話す。専門用語・内部用語ではなく、慣れ親しんだ語彙と概念を使う。
→ 「エンティティを登録」ではなく「お客様を追加」。

### 3. ユーザーの制御と自由
人は操作を間違える。**明示された非常口**を用意する。
→ 取り消し・やり直し・キャンセル。「戻れない」画面を作らない。

### 4. 一貫性と標準
同じ言葉・同じ見た目が、同じ意味であるようにする。
プロダクト内の一貫性（内部）と、業界慣習への追従（外部）の両方。
→ 「送信」と「登録」を同じ意味で混ぜて使わない。

### 5. エラーの予防
良いエラーメッセージより、**エラーが起きない設計**が上。
→ 制約と初期値で防ぐ。日付を自由入力させずカレンダーで選ばせる、など。

### 6. 記憶より認識
ユーザーに覚えさせない。選択肢・操作・情報を見える場所に置く。
→ 前の画面の内容を覚えていないと進めないフローを作らない。

### 7. 柔軟性と効率性
初心者には見えない形で、熟練者を速くする仕組みを用意する。
→ キーボードショートカット、履歴、保存済みフィルタ。（主に `2-web-app/` で効く）

### 8. 美的で最小限のデザイン
関係ない情報・めったに使わない情報を置かない。
情報を足すたびに、本当に重要な情報の相対的な見えやすさが下がる。

### 9. エラーからの認識・診断・回復を助ける
エラーコードではなく平易な言葉で、**何が問題か**と**どうすれば直るか**を書く。
→ 「エラーが発生しました」は禁止。「メールアドレスに @ が含まれていません」にする。

### 10. ヘルプとドキュメント
説明が要らないのが最善。必要な場合は、検索でき、文脈に沿い、具体的な手順を示す。

## 意思決定に効く法則

⚠️ 一般に広く引用される法則群。個別の一次文献は `references/sources.md` 参照（未照合のものあり）

### Hick の法則 — 選択肢が増えると決定が遅れる
選択肢の数と決定時間は対数的に比例する。
→ CTA を並べすぎない。ナビゲーションの項目を絞る。**「全部見せる」は親切ではない。**

### Fitts の法則 — 遠くて小さいものは押しにくい
ターゲットまでの到達時間は、距離が遠いほど・ターゲットが小さいほど長くなる。
→ 主要アクションは大きく、指／カーソルの近くに置く。
→ 画面の端・角は「無限に大きい」ターゲットとして機能する（カーソルが止まるため）。

### Miller の法則 — 短期記憶は 7±2 チャンク
実務上は **4〜5 が安全圏**。
→ 電話番号をハイフンで区切るように、情報は塊にして渡す。

### Jakob の法則 — ユーザーは他のサイトで大半の時間を過ごしている
だから**あなたのサイトも他と同じように動くことを期待している**。
→ 独創的なナビゲーションは、ほぼ常に負債になる。
   独創性は世界観（色・言葉・写真）で出し、**操作方法では出さない**。

### 美的ユーザビリティ効果 — 見た目が良いと使いやすいと感じる
見た目の良さは、軽微な使いにくさを覆い隠す。
→ 逆に言えば、**見た目の粗さはユーザビリティ問題として認識される。**
   余白・揃え・書体の統一は「装飾」ではなく機能。

### ポステルの法則 — 受け取りは寛容に、出力は厳密に
入力は幅広く受け入れ、出力は正確に。
→ 電話番号のハイフン有無、全角半角、前後の空白。**ユーザーに整形させない。**

### ピーク・エンドの法則 — 体験は「ピーク」と「終わり」で記憶される
→ 完了画面・送信後の体験に手を抜かない。そこが記憶に残る。

## 認知負荷の3分類

UI を評価するときの実務的な軸。

| 種類 | 中身 | どうするか |
|---|---|---|
| 課題内在性 | タスク本来の難しさ | 減らせない。分割して見せる |
| 課題外在性 | UIのせいで生じる無駄な負荷 | **これを潰すのがデザインの仕事** |
| 学習関連 | 理解・習熟のための負荷 | ここに認知資源を回せるようにする |

外在性負荷の典型：一貫しないラベル、探さないと見つからない主要導線、
読みにくい文字、意味の分からないアイコン、予測できない挙動。
