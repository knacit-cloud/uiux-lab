# アクセシビリティ — 守るべき数値

アクセシビリティは「障害のある人のための特別対応」ではなく、
**環境が悪いときに全員が助かる設計**。屋外の明るさ、片手操作、疲れた目、小さい画面。

ここは数値で判定できるものだけを置く。判断が要るものは各対象フォルダへ。

---

## WCAG 2.2 — レベル AA の主要基準

⚠️ 出典：[W3C WCAG 2.2 Quick Reference](https://www.w3.org/WAI/WCAG22/quickref/)（本文照合済）
日本の JIS X 8341-3 も WCAG に整合。公的機関案件では AA が事実上の要求水準。

### コントラスト

| 対象 | 基準 | SC |
|---|---|---|
| 通常テキスト | **4.5:1 以上** | 1.4.3 (AA) |
| 大きいテキスト（18pt以上 / 太字14pt以上） | **3:1 以上** | 1.4.3 (AA) |
| UI部品の境界・アイコン・グラフ | **3:1 以上** | 1.4.11 (AA) |
| 強化基準（通常テキスト） | 7:1 以上 | 1.4.6 (AAA) |

**よくある違反：** プレースホルダの薄いグレー、無効化ボタンの文字、
写真の上に白文字（背景次第で破綻する）、ブランドカラーの薄い方をテキストに使う。

> 無効（disabled）状態は WCAG のコントラスト要件から除外されるが、
> **「読めなくていい」わけではない。** 押せない理由が分からないUIになる。

### ターゲットサイズ

| 基準 | 値 | SC |
|---|---|---|
| 最小 | **24 × 24 CSS px** | 2.5.8 (AA) |
| 強化 | 44 × 44 CSS px | 2.5.5 (AAA) |

例外：①24px径の円が他ターゲットと交差しない間隔がある ②同機能の大きい代替がある
③文章中のインラインリンク ④ブラウザ標準UI ⑤本質的に必要（地図のピン等）
⚠️ 出典：[Understanding SC 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)（本文照合済）

**実務の既定値：モバイルを触る画面では 44×44 を目標にする。** 24 は下限であって目標ではない。

### 拡大・リフロー

- **200% までズームしても情報と機能が失われない**（1.4.4 AA）
- **幅 320 CSS px で横スクロールなしに読める**（1.4.10 AA）
  → 実質「スマホ縦持ちで横スクロールが出ない」こと
- `user-scalable=no` / `maximum-scale=1` は **禁止**（拡大を封じる）

### フォーカス

- **キーボードだけで全機能に到達・操作できる**（2.1.1 A）
- **フォーカス中の要素が他の要素に完全に隠れない**（2.4.11 AA）
  → 固定ヘッダー／固定フッターにフォーカス要素が潜り込む事故が典型。`scroll-margin-top` で回避
- `outline: none` を書くなら、`:focus-visible` で代替の見た目を必ず用意する
- `:focus` より **`:focus-visible`** を使う（マウスクリック時に枠が出るのを避ける）

### ドラッグ

- **ドラッグ操作には、ドラッグ以外の代替手段を用意する**（2.5.7 AA）
  → スライダーには数値入力、並べ替えには上下ボタン

## セマンティクス

ARIA を足す前に、**正しい HTML 要素を使う**。ARIA は不足を補うもので、代用ではない。

- アクションは `<button>`、遷移は `<a>`。**`<div onClick>` を書かない**
  （キーボード操作・スクリーンリーダー・中クリック・右クリックで新規タブ、が全部壊れる）
- 見出しは `<h1>`〜`<h6>` を**飛ばさず階層的に**。装飾目的で見出しレベルを選ばない
- 画像には `alt`。装飾画像は `alt=""`
- 装飾アイコンには `aria-hidden="true"`
- アイコンのみのボタンには **`aria-label`**
- フォーム部品には `<label>`（`for` で紐付け、またはラップ）。ラベルはクリック可能に
- 非同期の更新は `aria-live="polite"` で通知する
- ページ先頭に**スキップリンク**（本文へ飛ぶ）

## モーション

- **`prefers-reduced-motion` を尊重する。** 前庭障害のある人には実害がある
- アニメーションは `transform` と `opacity` のみ（他はレイアウトを再計算させる）
- `transition: all` は書かない。プロパティを列挙する
- アニメーション中でもユーザー入力で中断できるようにする

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

## 色だけに頼らない

情報を色**だけ**で伝えない（1.4.1 A）。
→ エラーを赤字だけで示さない。アイコンかテキストを添える。
→ グラフの系列を色だけで区別しない。形・パターン・直接ラベルを使う。

日本人男性の約5%に色覚特性がある。**赤と緑の区別は前提にできない。**

## 最低限の確認手順

1. **キーボードだけで**トップから主要導線を最後まで通す。Tab / Shift+Tab / Enter / Esc
2. ブラウザで **200% ズーム**、幅 **320px** にして崩れないか見る
3. コントラストを測る（DevTools のカラーピッカーに比率が出る）
4. `prefers-reduced-motion` をONにして動きが止まるか見る
5. 画像を全部非表示にして意味が通るか見る

自動チェック（axe DevTools 等）で拾えるのは全体の一部。
**キーボード通し操作は自動化で代替できない。**
