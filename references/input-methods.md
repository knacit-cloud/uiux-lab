# Claude に「見本」を渡す方法 — 質の順位

> ⚠️ 2026-11-20 調査。AI が公開記事・公式ドキュメントを照合。人間未確認。
> 出典は `references/sources.md` の #14〜#22。

**結論：スクショだけでは一番上には行かない。**
スクショは「どう見えるか」は伝わるが、**数値（色コード・余白・文字サイズ）と状態（ホバー・空・エラー）が伝わらない。**
Claude は足りない部分を「よくある平均値」で埋める。これがAIっぽい見た目になる原因。
2026年にアメリカで質を出している人は、**スクショ＋数値ファイル＋自己検証**の3点を組み合わせている。

---

## 質の順位

| 順位 | 渡すもの | 伝わるもの | 伝わらないもの | 使いどき |
|---|---|---|---|---|
| **S** | **数値ファイル**（`DESIGN.md`、既存の `tokens.css`、Figma MCP の `get_design_context`） | 色・書体・余白・角丸・部品の正確な値 | 雰囲気・構図 | **毎回。土台として必ず置く** |
| **A** | **実在アプリの画面DBをMCPで引く**（Mobbin / Refero / Lazyweb） | 実際に出荷された画面・**画面遷移（フロー）** | 自社ブランド | 新しい画面の型を決めるとき |
| **B** | **自分で撮るスクショ**（下の撮り方ルールを守ったもの） | 構図・密度・視線の流れ | 数値・状態（撮らなければ） | 「この感じ」を指定したいとき |
| **C** | Dribbble / Pinterest / Canva のモック | ムード・色の気分 | **ほぼ全部**。実装されていない絵なので、状態も制約もない | ブランドのムード決めだけ。**画面の型の見本にしない** |

### なぜ S が最優先か

- Figma の MCP は、ピクセル位置を「親の中で中央揃え」のような**関係**に、色の値を `brand-blue` のような**トークン名**に変換して渡す。スクショは精度が足りず、生のAPIデータは多すぎてモデルが溺れる、というのが Figma 側の説明（#17）
- Google は 2026-04 に `DESIGN.md` の仕様を公開した。上に YAML で数値、下に Markdown で「どう使うか」の理由を書く2層構造（#14）
- JSON のトークンは**値**しか持たないが、DESIGN.md は**ルール**（何をしてはいけないか）も持てる（#16）

### なぜ C を画面の見本にしないか

Dribbble や Canva の絵は**実装されていない**。押したらどうなるか、データが0件のときどうなるか、文字が長かったらどうなるか、が存在しない。
それを見本にすると、Claude は「絵としてはきれいだが使えない」画面を作る。
Canva は**ブランドキット（色・ロゴ・書体）の置き場**としては使える。画面の見本としては使わない。

## 必須：自己検証ループ

**どの渡し方でも、これがないと質は上がらない。**

1. Claude がローカルでページを立ち上げる（このリポジトリなら `node .claude/server.js`）
2. Claude が自分の出力をスクショする（ブラウザ操作ツール / Playwright）
3. 見本と横に並べて比較し、ズレを直す
4. 2〜3 を繰り返す。**数値は `getComputedStyle` で実測する**（目視だけで済ませない＝`AGENTS.md` §4）

Claude Code の実践記事でも、「サーバーを立ち上げ→スクショ→見本と比較→修正→再スクショ」を自動で回すのが質の決め手とされている（#18）。

## B：スクショの撮り方ルール

スクショを渡すなら、これを守ったものだけを渡す。守っていないスクショは C 扱い。

1. **1枚1論点。** 「このカードの余白」「このナビの階層」のように、何を見てほしいかを決めてから撮る
2. **幅を固定して撮る。** モバイル `375px`、デスクトップ `1440px`。DevTools のデバイスモードで撮る（実機のスクショは解像度がバラつく）
3. **状態も撮る。** 通常 / ホバー / フォーカス / 空（0件）/ エラー / 読み込み中。**通常だけ渡すと、残りは Claude の平均値になる**
4. **1行メモを必ず添える。** 「なぜ良いか」を書く。例：`見出しと本文の差が大きいので、ざっと見て構造がわかる`。**メモなしのスクショは平均化される**
5. **そのサイトの数値も一緒に取る。** `snippets/js/metrics.js` を開いたページで走らせ、本文サイズ・行間・余白の実測値を添える。これで B が S に近づく
6. **ファイル名の規約：** `YYYY-MM-DD_サイト名_対象_状態.png`（例：`2026-11-20_linear_sidebar_hover.png`）

### 保存場所（⚠️ 重要）

**このリポジトリは public。他社サイトのスクショをそのまま push しない。**
著作権・商標の問題になりうる。

| 置くもの | 場所 | git |
|---|---|---|
| スクショ画像そのもの | `.private/shots/<対象>/` | ❌ 追跡しない（`.gitignore` 済み） |
| URL・撮った日・1行メモ・実測値 | `references/teardowns/` に `1-web-site/teardown.md` の型で | ✅ 追跡する |

Claude には `.private/shots/` のパスを渡せば読める。public に出るのは**言葉と数値だけ**にする。

## 実際の渡し方（プロンプトの型）

```
uiux-lab/AGENTS.md と 0-core/ と <対象フォルダ>/ を読む。
ブランドは <プロダクト>/DESIGN.md を最優先で使う（ない値は uiux-lab の既定値）。

見本：
- .private/shots/2-web-app/2026-11-20_linear_sidebar_default.png
  → 項目の縦の間隔が詰まっていて、一覧性が高い。この密度にしたい
- .private/shots/2-web-app/2026-11-20_linear_sidebar_hover.png
  → ホバーは背景色だけ変わる。枠線を足さない

作る：<画面名>
終わったら自分でスクショして見本と並べ、ズレを3つ挙げて直すこと。
```

## 今使える道具（このアカウントの接続状況）

| 道具 | 状態 | 用途 |
|---|---|---|
| Figma MCP | ✅ 接続済み | デザインがFigmaにあるなら **S** で渡せる。最優先 |
| Canva | ✅ 接続済み | ブランドキットの置き場。画面の見本には使わない |
| ブラウザ操作（内蔵ブラウザ） | ✅ あり | 自己検証ループ・実在サイトの実測 |
| Mobbin MCP | ❌ 未接続 | 有料。ネイティブアプリの画面とフローが最も厚い |
| Refero MCP | ❌ 未接続 | Web と iOS。画面・フロー・DESIGN.md化したスタイル集がある |

**入れるなら1つだけ：** アプリ（`3-mobile` / `2-web-app`）を本格的にやるなら Mobbin か Refero のどちらか。
両方は要らない。LP 中心なら今の構成（Figma＋自分のスクショ＋metrics.js）で足りる。
