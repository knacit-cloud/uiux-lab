# 3-mobile — 扱う範囲

> 🔲 **未着手。** ここは SCOPE のみ。着手するときに、まずこの SCOPE を確定させてから中身を書く。

## 対象

**ネイティブアプリ（iOS / Android）。**

「スマホで見た Web サイト」は**ここではない**。それは `1-web-site` のレスポンシブの話。
ここは「OS の上で動くアプリ」として作るときの話。

## この対象の前提

| 前提 | 帰結 |
|---|---|
| 入力は指。カーソルがない | hover がない。ターゲットは大きく |
| 片手で持つことが多い | **画面上部は届きにくい**。主要操作は下部に |
| 画面が小さい | 1画面1タスク。階層で分ける |
| OS に作法がある | **iOS と Android で違う**。逆らうと使いにくい |
| 通知・バックグラウンド・オフラインがある | 状態が中断される前提で設計する |
| インストールというハードルを越えて来ている | Web より継続利用が期待できる |

## ここに入れる予定のもの

- **iOS HIG と Material Design 3 の差分**（何を揃え、何を分けるか）
- **ナビゲーション**：タブバー、スタック、モーダル、戻るの作法（iOSのスワイプバック / Androidの戻る）
- **タッチターゲット**：iOS 44×44pt / Android 48×48dp
- **サムゾーン**（片手で届く範囲）と主要操作の配置
- **ジェスチャ**：スワイプ、長押し、プル・トゥ・リフレッシュ。**必ず代替手段を用意する**
- **セーフエリア**：ノッチ、ダイナミックアイランド、ホームインジケータ
- **状態**：オフライン、通信失敗、バックグラウンド復帰、権限拒否
- **権限リクエストのタイミング**（起動直後に全部聞かない）
- **オンボーディング**と初回起動体験
- **プラットフォームのアクセシビリティ**：VoiceOver / TalkBack、Dynamic Type、視差軽減
- **クロスプラットフォーム実装**（React Native / Flutter）でどこまで揃えるか
- ストア掲載（スクリーンショット、説明文）— UX の一部として

## ここに入れないもの

- Web サイトのレスポンシブ対応 → `1-web-site/`
- 管理画面のデータテーブル設計 → `2-web-app/`
- コントラスト・タイポの基本数値 → `0-core/`（ただしプラットフォーム固有の値はここ）
