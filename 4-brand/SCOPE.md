# 4-brand — 扱う範囲

> ✅ SCOPE 作成（2026-11-20）。人間の確認待ち。

## このフォルダだけ性質が違う

`0-core`〜`3-mobile` は「**何を作るか**（対象）」で分けている。
`4-brand` は「**誰のものを作るか**（会社・プロダクト）」の話。軸が直交している。

```
            1-web-site   2-web-app   3-mobile
自社           ●            ●           ─
顧客A社        ●            ─           ●
```

- 対象フォルダ（列）＝ どの会社でも同じ「作法」
- ブランド（行）＝ その会社だけの「固有値」（色・書体・声・角丸の性格）

**ここに置くのは「固有値の決め方」と「テンプレート」だけ。**
各社の実際の値（自社の色コードなど）は、そのプロダクトのリポジトリ直下に `DESIGN.md` として置く。
ここに顧客の値を貯めない（このリポジトリは public）。

## ここに入れるもの

- ブランドを定義する手順（`brand-definition.md`）
- `DESIGN.md` のテンプレート（`DESIGN.template.md`）— Google の公開仕様に準拠
- 同じブランドを「サイト用」「アプリ用」にどう出し分けるか

## ここに入れないもの

- コントラスト比・最小文字サイズなどの基準 → `0-core/`（ブランドはこれを下回れない）
- LP の構成、管理画面の密度 → 各対象フォルダ
- 顧客の実際のブランド値 → 各プロダクトのリポジトリ

## 優先順位（衝突したとき）

1. `0-core` の「絶対に破らない線」（`AGENTS.md` §1）— **ブランドでも上書きできない**
2. プロダクトの `DESIGN.md`（ブランド固有値）
3. 対象フォルダの既定値
4. `AGENTS.md` §2 の既定値
