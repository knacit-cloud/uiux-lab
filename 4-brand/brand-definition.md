# ブランドを定義する手順

> ⚠️ 2026-11-20 作成。手順は AI が公開資料（#14〜#16）を元に組んだもの。実案件で1回通すまで仮。

**ゴール：その会社の `DESIGN.md` が1枚できること。**
それをプロダクトのリポジトリ直下に置き、`CLAUDE.md` / `AGENTS.md` に「UI を作る前に DESIGN.md を読む」と1行足す。
これで Claude は毎回同じブランドで作る（#14）。

---

## 手順（6工程）

### ① 事実を集める（決める前に）

| 集めるもの | どこから |
|---|---|
| 既存のロゴ・色・書体 | 既存サイト（`metrics.js` で実測）、Canva ブランドキット、名刺・パンフ |
| 誰に向けた会社か | 本人に聞く。**推測で埋めない** |
| 競合3社の見た目 | 競合サイトを `metrics.js` で実測（`1-web-site/teardown.md` の型） |
| 使う場所 | サイトだけか、アプリもあるか、印刷物もあるか |

既存サイトがあるなら、**ゼロから作るより先に「今の値」を抽出する。**
ブラウザで開いて計算済みスタイルから色・書体・余白・角丸を拾い、それを叩き台にする。

### ② 性格を3語で決める

例：`誠実・静か・精密`。**形容詞は3つまで。** 5つ並べると全部が薄まる。
各語に「**だから何をしない**か」を1つずつ付ける。

| 性格 | だからしない |
|---|---|
| 誠実 | 誇張した数字・「業界No.1」を使わない |
| 静か | 彩度の高い色を広い面積に使わない |
| 精密 | 角丸を大きくしない（丸いとやわらかく見える） |

この「しない」が `DESIGN.md` の **Do's and Don'ts** になる。AI に一番効くのはここ。

### ③ 色を決める（役割で）

色は**名前でなく役割**で決める（`0-core/color-spacing.md` の意味トークン）。

- `primary` — 主要ボタン・リンク。**1色**
- `neutral` 系 — 背景・文字・線。グレーの段階
- `accent` — 使うなら1色。面積は小さく
- `danger` / `success` / `warning` — 状態。ブランド色と混同しない

**決めたら必ず `0-core/accessibility.md` の 4.5:1 を通す。** `DESIGN.md` の lint がコントラストを警告してくれる（下記）。

### ④ 書体を決める

- 日本語1書体＋欧文1書体まで（`0-core/typography.md`）
- ウェイトは 400 / 700 の2つが既定
- サイズの段階（`display` / `heading` / `body` / `caption`）を決める。本文は 16px 以上

### ⑤ 形を決める（角丸・影・余白の性格）

- 角丸は**1〜2種類**。性格に合わせる（精密→4px、親しみ→12px など）
- 影は使うなら**1〜2段階**。使わないならそう書く
- 余白は 8px グリッド。**密度だけはサイトとアプリで変える**（下記）

### ⑥ DESIGN.md に書いて lint する

`DESIGN.template.md` をコピーして埋める。

```bash
npx @google/design.md lint DESIGN.md
```

- 参照切れ（`{colors.xxx}` が存在しない）は**エラー**
- コントラスト不足・primary 未定義・使われていないトークンは**警告**（#15）
- `export` で Tailwind 設定や DTCG 形式に書き出せる

## サイトとアプリで出し分ける

**ブランド（色・書体・性格）は共通。密度と動きだけ変える。**

| 項目 | サイト（`1-web-site`） | Webアプリ（`2-web-app`） | ネイティブ（`3-mobile`） |
|---|---|---|---|
| 色・書体・ロゴ | 共通 | 共通 | 共通（ただし書体は OS 標準を検討） |
| 余白 | 広い | **詰める** | 中間。OS の既定に寄せる |
| 本文サイズ | 16–18px | 14–16px（`2-web-app/SCOPE.md` の実測参照） | OS の Dynamic Type / sp に従う |
| 色の面積 | ブランド色を大きく使ってよい | **ブランド色は操作要素だけ** | OS のマテリアル（後述）と喧嘩させない |
| 動き | 控えめな演出は可 | 状態変化だけ | OS の作法に従う |

`DESIGN.md` は1枚にして、密度の違いは `## Layout` に「サイト」「アプリ」の小見出しで書く。
ファイルを2枚に分けると、色がズレ始める。

### ネイティブアプリの注意（2026年時点）

- iOS 26 以降は **Liquid Glass**（周囲の色を映す半透明の素材）がナビやタブバーに使われる。Apple は、内容と文脈に応じて変化する素材だと説明している（#19）
- Android は **Material 3 Expressive** で、色・形・動き・触覚フィードバックをより積極的に使う方向（#20）
- つまり**ナビゲーション層は OS に任せ、ブランド色はコンテンツ側に置く**のが衝突しない置き方。タブバーをブランド色で塗りつぶすと OS の見た目と喧嘩する
- 詳細は `3-mobile/` 着手時に一次資料（HIG / m3.material.io）で確定させる。**ここは方向性のメモ止まり**
