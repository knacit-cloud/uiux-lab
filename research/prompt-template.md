# プロンプトの型

> `findings.md` から組み立てた型。**各ブロックの右に、なぜ入れるかの R 番号。**
> 研究で直接確かめた型ではない。研究の結果を組み合わせた**仮説**。実際に使って `LESSONS.md` に結果を残す。

## 型

```xml
<instructions>                                         <!-- R-15 指示と素材を分ける -->
uiux-lab/AGENTS.md・0-core/・<対象フォルダ>/ を読んでから作る。
DESIGN.md にない色・書体・角丸・影を足さない。         <!-- R-02 見た目は明示で渡す -->
この依頼で名前が出ている作業は、全部操作できるようにする。 <!-- R-06 33% の失敗 -->
数字は下の原稿にあるものだけ使う。合計・件数を合わせる。   <!-- R-06 26% の失敗 -->
</instructions>

<context>                                              <!-- R-15 理由を添える -->
使う人：<intake の「誰が使うか（1人）」>                 <!-- R-03 -->
その人にしてほしいこと：<1つ>
なぜ：<この画面がその人の何を解決するか>
</context>

<brand>
<DESIGN.md のパス、または中身>                            <!-- R-02 -->
</brand>

<references>                                           <!-- R-12 見本は主要な入力 -->
<reference file=".private/shots/....png">
  取り入れる所：<見出しの組み方だけ>                    <!-- R-08 見本に引っ張られる -->
  取り入れない所：<色・写真・文言>
</reference>
</references>

<content>                                              <!-- R-09 文字は画像から読ませない -->
<原稿をそのまま>
</content>

<process>
1. 作る前に、方向を3案出す。                            <!-- R-13 -->
   それぞれ「AI がよく出す型にどのくらい近いか」を高・中・低で添える。
2. 私が1つ選んでから作る。
3. 作ったら描画してスクショし、次の観点で 1〜5 点をつけ、    <!-- R-11 観点と点数 -->
   3点以下の観点を直す。これを最大3回。
   観点：視覚的階層／余白の一貫性／<context>の行動への導線／
        intake/ai-bias-check.md への該当／見本との差
4. 主要な操作を実際にクリックして動くか確かめる。          <!-- R-11 操作テスト -->
5. 最後に、点数と直した所と残した所を報告する。
   自己評価は参考値として扱う。                            <!-- R-14 -->
</process>
```

## 下がる書き方（避ける）

| 書き方 | なぜ下がるか |
|---|---|
| 「〇〇業界向けのおしゃれなサイト」だけ | 業種を書いても見た目は変わらない（R-02） |
| スクショだけ渡して「これと同じ感じで」 | 再現できるのは半分程度（R-07）。どこを取るか伝わらない（R-08） |
| 見本に真似させたくない部分が写ったまま | 例に強く従う（R-08） |
| 「いい感じに直して」「見直して」 | 観点のない見直しは効きにくい（R-10） |
| 数字を「適当に入れておいて」 | 合わない数字が 26%（R-06） |
| 1案だけ頼む | 典型的な1案に寄る（R-04, R-13） |
