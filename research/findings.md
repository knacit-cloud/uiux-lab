# 研究で分かったこと

> 2026-11-20 作成。各項目の真下に根拠と出典。出典番号は `references/sources.md`。
> `⚠️` = AI が本文を照合 ／ `🔍` = 検索結果の抜粋のみ（本文未照合）。**人間未確認。**

## A. 偏る（AI っぽくなる）

### R-01 今のモデルは要件を満たすが、デザインの多様性は人間を大きく下回る

- **根拠：** 2026年の最新モデル15種に 2,400 件の HTML デザインを作らせた比較。
  - 要件の充足：**全モデルが 90% 超**（最高 99.2%。人間の基準は 98.0%）
  - 独自性（同じ依頼で、別モデルの作品とどれだけ違うか）：モデル **0.592** ／ 人間 **0.764**
  - 表現の幅（同じ目的で業種・中身だけ違う2つの依頼に、同じモデルがどれだけ違う作品を出すか）：モデル **0.581** ／ 人間 **0.902**
  - 総合点：モデル最高 65.5 ／ 人間 92.3
- **言えること：** 「ちゃんと動く・要件は満たす」はもう問題ではない。**問題は似ていること。**
- **言えないこと：** この研究は temperature・ペルソナ・「多様にして」などの対策を**試していない**。対策の効果はここからは言えない
- 出典：#36 Design Creativity Bench（arXiv 2610.11539）⚠️

### R-02 依頼文の業種・中身を変えても、デザインはほとんど変わらない

- **根拠：** 同じモデルに「目的は同じで、業種と中身だけ違う」依頼を2つ出すと、作品の違いは 0.581 にとどまる。まったく別の課題を2つ出したときは 0.811 まで上がる
- **言えること：** 「製造業向けです」「士業です」と書き足すだけでは、AI は同じ見た目を出す。
  **見た目の判断（色・書体・構成の型）は、業種とは別に明示的に渡す必要がある**
  → `4-brand/DESIGN.md`、`intake/items.md` #4・#5 を聞く理由
- 出典：#36 ⚠️（論文内の見出し「Differentiating the prompt does not differentiate the design」）

### R-03 一般的なデータだけで作ると、汎用的な解に寄る。使う人の情報で導くと防げる

- **根拠：** クラウドソーシングで集めた「対象ユーザーが好む部品」を与えて UI を作らせた研究。
  著者は、汎用データだけで学習した LLM は、対象ユーザーの知見で明示的に導かない限り、デザインの選択を汎用解へ均質化する危険がある、と結論している
- **言えること：** `intake` で「誰が使うか（1人）」を必須にしている根拠
- 出典：#37 CrowdGenUI（arXiv 2411.03477）🔍

### R-04 偏りの原因の1つは「人間の評価データが典型的な答えを好む」こと（典型性バイアス）

- **根拠：** 調整（アライメント）後のモデルが同じような答えに寄る現象（モード崩壊）の原因として、
  人間の好みのデータに含まれる**典型性バイアス**を理論と実データで示した研究
- **言えること：** 「AI がわざと手を抜いている」のではなく、**一番無難な答えを出すように訓練されている。**
  だから「無難でない判断」は人間が渡すしかない
- **注意：** 文章生成の研究。UI への当てはめは**外挿**
- 出典：#38 Verbalized Sampling（arXiv 2510.01171）🔍

### R-05 個人の生産性が上がっても、集団としては似てくる

- **根拠：** LLM 支援でアイデア出しをした実験で、個人の案の数は増えたが、集団レベルの均質化は強まった（Anderson ら 2024）。
  エッセイ 2,200 本の分析でも、人間の文章のほうが1本増えるごとに新しい発想を多く足した
- **言えること：** 同じ AI・同じスキルを使う人が増えるほど、世の中の UI は似てくる。
  他社と同じスキルを入れても差は出ない（`references/skills.md` の「入れない」の根拠）
- **注意：** 文章・アイデアの研究。UI への当てはめは**外挿**
- 出典：#45（arXiv 2603.21228 の先行研究まとめ）🔍

## B. 質が下がる

### R-06 名前の出たワークフローの操作部品を作り忘れる、サンプルデータの数字が合わない

- **根拠：** R-01 と同じ研究で、要件を落としたときの**内訳**：
  - 依頼文で名前が出ている作業の**操作部品がない：33%**
  - サンプルデータの**件数や合計が合っていない：26%**
- **言えること：** AI の失敗は「見た目」より「**言われた作業ができない**」「**数字が嘘**」のほうが多い。
  → `intake/items.md` A1（一番多い作業）を必須に、C3（意味のない数字）を点検項目に
- 出典：#36 ⚠️

### R-07 スクショだけ渡すと、文字と細部の再現が弱い

- **根拠：** 実在の Web ページ 484 件をスクショからコードにする比較。モデルは**画面要素の拾い漏れ**が主な弱点だった。
  人間の評価では、最も良い条件でも**元のページと置き換えてよいと判断されたのは 49%**
- **言えること：** スクショ1枚で「これと同じものを」は半分しか成功しない（2024年時点のモデル）
- 出典：#39 Design2Code（arXiv 2403.03163）🔍

### R-08 「見本」と「指示」が食い違うと、見本に引っ張られる

- **根拠：** Anthropic の公式ガイドは、Claude は例と細部に強く従うので、**例を、望む振る舞いに合わせること**、と注意している
- **言えること：** 「ここは真似しないで」と書いても、渡したスクショに写っていれば真似される危険がある。
  **真似させたくない部分が写った見本は、渡す前に切り抜く**か、取り入れる所を明示する
- 出典：#44 Anthropic Prompting best practices 🔍

## C. 質が上がる

### R-09 スクショに「中身の文字」を添えると上がる

- **根拠：** R-07 の研究で、ページの文字を先に抜き出してスクショに添える方法（text-augmented）が、**ほとんどのモデルで大きく改善**した
- **言えること：** 見本を渡すときは、**原稿（文字）を別で渡す。** 画像から読ませない
- 出典：#39 🔍

### R-10 「自分で見直して」と言うだけでは効きにくい（2024年）

- **根拠：** R-07 の研究で、前回の出力と見本を見比べて直させる方法（self-revision）は、**自分の出力を改善できたモデルが少なかった**
- **言えること：** 単に「見比べて直して」では弱い。R-11 と合わせて読む
- 出典：#39 🔍

### R-11 描画して、評価をつけ、操作も試すループは大きく効く（2025〜2026年）

- **根拠：**
  - ページを描画してスクショを撮り、視覚モデルが**説明と見た目の点数**をつけ、さらに**GUI エージェントが実際に操作して**テストするループ。
    Claude 3.5 Sonnet で **正答率 26.4% → 51.9%、見た目の点数 3.0 → 3.9**
  - 実際の利用者の依頼（WebDev Arena）で、視覚モデルを**批評役**にして構造化した指摘を返し、反復修正させると、**1回で出すより有意に高品質**
- **言えること：** R-10 との違いは、①**観点つきの評価（点数・指摘）**、②**操作のテスト**、③**反復**。
  → `intake/README.md` ⑦、`references/input-methods.md` の自己検証ループは、**観点と点数つきで回す**
- 出典：#40 WebGen-Agent（ICLR 2026）🔍、#41 Vision-Guided Iterative Refinement（ICLR 2026 Workshop）🔍

### R-12 参照データ（見本の知識）を抜くと品質が一番落ちる

- **根拠：** UI 生成の仕組みから部品を1つずつ外して測った研究。**参照知識の検索を外したとき、品質指標（FID、低いほど良い）が 23.76 → 42.56 と最も悪化**した。
  文章・画像・アイコンの各部品を外したときの悪化は 0.3〜1.0 程度
- **言えること：** 見本は「あれば良い」ではなく**主要な入力。** Mobbin / Refero / 自分のスクショを渡す根拠
- **注意：** 画像生成ベースの UI 生成の研究。コードを書く Claude にそのまま当てはまるかは**外挿**
- 出典：#43（arXiv 2412.20071）⚠️

### R-13 「答えを1つ」でなく「複数の候補を確率つきで」と頼むと、多様性が上がる

- **根拠：** 「答えを5つ、それぞれの確率つきで」と頼む方法で、創作文章の多様性が**直接頼んだ場合の 1.6〜2.1 倍**。能力の高いモデルほど効果が大きい傾向
- **言えること：** `intake` 型C（おまかせなら3案）の根拠。**「3案、それぞれどのくらいありがちか」まで言わせる**とさらに効く可能性
- **注意：** 文章での研究。UI デザインでの効果は**未検証・外挿**
- 出典：#38 🔍

### R-14 AI の UI 批評は、例と視覚的な指示で上がるが、人間にはまだ届かない

- **根拠：** デザイナー7人による 983 画面・3,059 件の批評データを、例（few-shot）と視覚的な指示で使うと、AI の批評の質が **55% 向上**。それでも著者は、LLM の評価は**人間の評価者に及ばない**としている
- **言えること：** AI の自己点検（`ai-bias-check.md`）は**一次ふるい。** 最終判断は人間
- 出典：#42 UICrit（UIST 2024）🔍

### R-15 明示的な指示、理由の説明、指示と素材の区切りで上がる

- **根拠：** Anthropic の公式ガイド：
  - 明確で具体的な指示によく反応する。期待以上を望むなら**明示的に頼む**
  - **なぜその振る舞いが大事かという理由**を添えると、目的を理解して的を絞る
  - 指示・文脈・例・入力を **XML タグで分けると誤解が減る**。例は **3〜5 個**
- 出典：#44 🔍

## 研究同士の食い違い

| 論点 | 一方 | もう一方 | このリポジトリの扱い |
|---|---|---|---|
| 自己修正は効くか | 効きにくい（R-10、2024年のモデル） | 大きく効く（R-11、2025〜26年） | **観点・点数・操作テストつきで回す**。「見直して」だけにしない |
| 多様性は上げられるか | 対策は限定的という先行研究が多い（#36 の関連研究） | 頼み方で 1.6〜2.1 倍（R-13、文章） | 3案は出す。ただし**ブランドの判断（R-02）を渡すほうが優先** |
