# research — AI 研究で分かったこと

このリポジトリの「こうすべき」の**根拠の層**。
`intake/` や `0-core/` が「何をするか」を書き、ここは「**なぜそれが効くと言えるのか**」をデータで書く。

## 書き方のルール

1. **1項目 = 1つの主張。** 主張の真下に「根拠（数字）」と「出典」を必ず置く
2. **研究が言っていないことを書かない。** 研究の条件（いつの、どのモデルで、何を測ったか）を書き、
   UI 以外の研究を UI に当てはめているときは **「外挿」** と明記する
3. **研究同士が食い違うときは、両方書く。** 片方だけ採らない
4. 検証記号は `references/sources.md` と同じ：`⚠️` 本文照合済（AI）／`🔍` 抜粋のみ／`✅` 人間確認済
5. 新しい主張は `R-` 番号をつけて `findings.md` に足し、`sources.md` にも登録する

## ファイル

| ファイル | 中身 |
|---|---|
| `findings.md` | 研究で分かったこと。**偏る／質が下がる／質が上がる**の3分類 |
| `prompt-template.md` | `findings.md` から組み立てたプロンプトの型。各行に根拠の R 番号 |

## 研究から言えることの要約（2026-11 時点）

1. **今の AI の UI は「合格点だが、どれも似ている」。** 要件はほぼ満たすが、多様性は人間を大きく下回る（R-01）
2. **業種や中身を変えるだけでは、デザインは変わらない。** 見た目の判断を明示的に渡す必要がある（R-02）
3. **一番効くのは「描画して見て直す」ループ。** ただし「見直して」と言うだけでは効きにくく、観点と評価を与える必要がある（R-10, R-11）
4. **見本（参照データ）を抜くと品質が一番落ちる。** 参照は飾りではなく主要な入力（R-12）
5. **AI の自己評価は人間に届かない。** 最後は人間が見る（R-14）
