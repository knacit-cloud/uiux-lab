# UXライティング（BtoB日本語）

**日本語BtoBサイトの弱点は、デザインより先に文章にある。**
レイアウトを直すより、言葉を直す方が効く場面が圧倒的に多い。

---

## 3つの原則

### 1. 主語をユーザーにする

| ✕ 自分主語 | ○ ユーザー主語 |
|---|---|
| 私たちは業務改善を支援します | 何から手をつけるべきかが分かります |
| 豊富な経験でサポートいたします | 現場の非効率を、外からの視点で見つけます |
| 最適なソリューションをご提案 | 3ヶ月後、確認の電話が減ります |

**「私たちが何をするか」ではなく「あなたに何が起きるか」。**

### 2. 抽象を具体に落とす

抽象語は書き手には気持ちいいが、読み手には何も伝わらない。

| 抽象 | 具体 |
|---|---|
| 業務効率化 | 受発注の転記作業をなくす |
| DX推進 | FAXで来た注文を、自動でデータにする |
| 生産性向上 | 月42時間の作業を18時間にする |
| 最適化 | 承認を3段階から1段階にする |
| 伴走支援 | 月2回、現場に入って一緒に手を動かす |

**チェック方法：** その文から、あなたの会社名を消して競合の名前を入れる。
そのまま成立するなら、**何も言っていない。**

### 3. 背負えないことを言わない

`trust-btob.md` と同じ。実態と釣り合わない言葉は、バレた瞬間に他の全記述の信憑性を消す。

| 背負えない | 言い換え |
|---|---|
| 専門家が診断します | 外からの視点で見つけます |
| 豊富な実績 | （具体例を1つ出す。なければ書かない） |
| 業界最安値 | 月2万円から始められます |
| 完全サポート | 月2回のミーティングで伴走します |
| 追加料金なし | 料金は月額のみ。別途費用が出る場合は事前にお知らせします |

## 見出しの書き方

### 型

| 型 | 例 | 使いどころ |
|---|---|---|
| **課題提示** | 「何から手をつけるべきか、分からない」 | ヒーロー・課題セクション |
| **結果提示** | 「3ヶ月後、確認の電話が月40件から5件に」 | 実績・事例 |
| **問いかけ** | 「こんな状態になっていませんか」 | 課題への共感 |
| **手順提示** | 「診断 → 種まき → 育成 → 開花」 | 流れ |
| **断定** | 「まず、現状を言葉にするところから」 | CTA |

### 長さ

- ヒーロー見出し：**20〜35字**。それ以上は読まれない
- セクション見出し：**15〜25字**
- 1行に収まらないなら、**言葉が多すぎるサイン**

### やらないこと

- **体言止めの多用**（「業務効率化の実現」）。動きがなく、他人事に聞こえる
- **英語のキャッチコピー**（`Empower Your Business`）。日本のBtoBでは意味が届かない
- **「〜という」「〜における」「〜に関する」** — 削っても意味が変わらない
- **見出しとサブコピーが同じことを言っている** — サブは補完であって言い換えではない

## 削る技術

日本語ビジネス文は、**そのままだと3割は削れる。**

### 冗長表現の対応表

| 冗長 | 簡潔 |
|---|---|
| することができます | できます |
| という点において | で |
| を行う / を実施する | する（「作業を行う」→「作業する」） |
| に関しまして | について |
| させていただきます | します |
| いたしますので | するので |
| となっております | です |
| ご覧いただけます | 見られます |
| 〜することが可能です | 〜できます |
| 〜のような形で | 〜で |

### 実例

```
✕ 弊社では、お客様の課題に関しまして、無料での診断を実施させていただくことが可能となっております。
   （54字）

○ 課題を無料で診断します。
   （12字）
```

**削っても情報は1つも失われていない。** 丁寧さは語尾の敬体で足りる。

### 一文の長さ

- **一文は 40〜60字まで。** 60字を超えたら切る
- 「〜し、〜し、〜します」と繋げない。**句点で切る**
- 修飾語は被修飾語の直前に置く

## ボタン・リンクの文言

**動詞で、具体的に、ユーザー主語。**

| ✕ | ○ |
|---|---|
| 送信 | 無料診断を申し込む |
| お問い合わせ | 30分の無料相談を予約する |
| 詳細 / 詳しく見る | 料金プランを見る |
| こちら | 導入事例を読む |
| Click Here / More | （日本語にする） |
| 資料DL | 資料をダウンロード（PDF・2.4MB） |

**ボタンを押した後に起きることを、ボタンに書く。**
リンク先がPDFや外部サイトなら、それも書く。

```html
<a href="/doc.pdf" download>
  サービス資料をダウンロード
  <span class="text-sm text-muted">（PDF・2.4&nbsp;MB）</span>
</a>
```

### CTA下の摩擦除去コピー

BtoBのCTAで止まる理由はほぼ「押したら何が起きるか分からない」。

```
[ 無料診断を申し込む ]
所要3分・費用はかかりません・営業のご連絡はしません
```

**具体的な不安を名指しで消す。** 「お気軽にどうぞ」では何も消えていない。

## エラーメッセージ

**何が起きたか ＋ どう直すか。** 両方書く。

| ✕ | ○ |
|---|---|
| エラーが発生しました | 送信できませんでした。時間をおいて再度お試しください |
| 入力エラー | メールアドレスに「@」が含まれていません |
| 不正な値です | 電話番号は数字のみで入力してください |
| 必須項目です | 会社名を入力してください |
| ファイルサイズオーバー | ファイルは8MBまでです。圧縮するか、URLをご記入ください |

**ルール：**
- **ユーザーを責めない。**「入力が間違っています」→「◯◯を確認してください」
- エラーコードを出さない（出すならサポート用に小さく併記）
- 復旧手段を必ず示す。八方塞がりなら**代替の連絡先**を出す

## マイクロコピー

小さいテキストが、実は摩擦を一番減らす。

| 場所 | 例 |
|---|---|
| 入力欄のヒント | 「ハイフンあり・なしどちらでも構いません」 |
| 任意項目 | 「任意 — 分かる範囲で構いません」 |
| ファイル添付 | 「8MBまで / PDF・画像・Excel」 |
| 送信ボタン下 | 「送信後、確認メールが届きます」 |
| 完了画面 | 「3営業日以内にご入力のメールアドレスへお送りします。届かない場合は迷惑メールフォルダもご確認ください」 |
| 料金の但し書き | 「表示は税抜です。課題の数によって期間が変わります」 |

## 完了画面・自動返信メール

**ピーク・エンドの法則。** ここが記憶に残る。手を抜かない。

必ず書く4つ：
1. 受け付けたことの明示（「送信しました」で終わらせない）
2. **次に何が・いつ起きるか**
3. 届かない場合の対処
4. 問い合わせ先

```
無料診断のお申し込みを受け付けました。

3営業日以内に、ご入力いただいたメールアドレス宛に診断結果をお送りします。
自動返信メールが届いていない場合は、迷惑メールフォルダをご確認ください。

ご不明な点は hello@example.com までお気軽にどうぞ。
```

## 日本語の表記ルール

プロジェクトごとに決めて**統一する**。ブレは素人っぽさの直接的な原因。

| 項目 | 決めごとの例 |
|---|---|
| 敬体 | 「です・ます」で統一（「である」を混ぜない） |
| 漢字/ひらがな | 「事」→「こと」、「時」→「とき」、「出来る」→「できる」、「下さい」→「ください」 |
| 数字 | 半角。「3つ」「2万円」 |
| 英数字の前後 | **半角スペースを入れない**（和欧混植は CSS の `font-family` 順で処理） |
| 記号 | 三点リーダ `…`、波ダッシュ `〜`、引用符 `「」` |
| カギ括弧 | 強調は「」。二重は『』 |
| 感嘆符 | **使わない**（BtoBでは軽く見える） |
| 単位 | 数字と単位の間はノーブレークスペース `10&nbsp;MB` |
| 会社名 | 正式名称を1回出したら以降は略称。**表記ゆれを作らない** |

### 英語表記

- **米綴りに統一**（center / organization / -ize）
- 固有名詞・ブランド名には `translate="no"`

```html
<span translate="no">Knacit</span>
```

## 書いた後のチェック

- [ ] 自社名を競合名に置き換えても成立する文が残っていないか
- [ ] 「することができます」「を行う」「させていただき」を検索して削ったか
- [ ] 一文が60字を超えていないか
- [ ] ボタンのラベルが「送信」「詳細」になっていないか
- [ ] エラーメッセージに**直し方**が書いてあるか
- [ ] 抽象語（効率化・最適化・DX・ソリューション）に具体例が添えてあるか
- [ ] 背負えない約束をしていないか
- [ ] 表記ルールが全ページで揃っているか
- [ ] **声に出して読んで、詰まらないか**（一番確実な検査）
