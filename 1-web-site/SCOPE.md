# 1-web-site — 扱う範囲

## 対象

**読ませて、信用させて、行動させるページ。**

- LP（ランディングページ）
- コーポレートサイト
- サービス紹介ページ
- 採用ページ

滞在時間は短い。ユーザーは**ログインしていない**。**離脱は1クリック**。
これが `2-web-app` との決定的な違い。

## この対象の前提

| 前提 | 帰結 |
|---|---|
| ユーザーは初めて来た | 説明なしで分かる必要がある。学習を期待できない |
| いつでも離脱できる | 最初の10秒で価値を伝えないと終わり |
| 信用がゼロから始まる | 「誰が言っているか」を示す必要がある |
| 検索とSNSから来る | パフォーマンスとOGPが集客に直結する |
| 目的は1つ（コンバージョン） | 導線を絞る。選択肢を増やすと決まらない |

## ここに入れるもの

- ページ全体の構成とセクション順序
- ファーストビュー（fold）の設計
- ヒーローと CTA
- BtoB における信頼の作り方
- 問い合わせ／申込フォーム
- Core Web Vitals とSEO的な最低ライン
- OGP・メタ情報

## ここに入れないもの

- **データテーブル、フィルタ、ソート、一括操作** → `2-web-app/`
- **ログイン後の情報設計、権限、状態管理** → `2-web-app/`
- **タッチジェスチャ、OS固有の作法** → `3-mobile/`
- コントラスト・タップ領域・タイポの数値基準 → `0-core/`

## 混在の警告

**LP に管理画面の作法を持ち込むと死ぬ典型：**
- 情報密度を上げる（LPは余白が価値。詰めると安く見える）
- 選択肢を全部見せる（LPは1つに絞る）
- 機能一覧を表で並べる（LPは「あなたの何が解決するか」を語る）

**逆に、管理画面に LP の作法を持ち込むと死ぬ典型：**
- 巨大なヒーロー、広大な余白（毎日使う画面で1画面あたりの情報量が減るのは苦痛）
- スクロール連動アニメーション（作業の邪魔）
