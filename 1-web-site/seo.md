# SEO — 集客

**LPとコーポレートサイトは、見られなければ存在しないのと同じ。**
ここは Google の一次情報に基づいて書く。**俗説を持ち込まない。**

⚠️ 出典：[Google Search Essentials](https://developers.google.com/search/docs/essentials) /
[SEO Starter Guide](https://developers.google.com/search/docs/fundamentals/seo-starter-guide)（本文照合済・2026-07時点）

---

## まず、Google が「効かない」と明言しているもの

**世間で語られている施策の多くを、Google 自身が否定している。**
ここを知らないと、効かないことに時間を使う。

| よく言われること | Google の見解 |
|---|---|
| キーワードを詰め込む | **スパムポリシー違反。** キーワード密度に意味はない |
| `<meta name="keywords">` を書く | **Google は使っていない** |
| 文字数を◯◯字以上にする | 「魔法の文字数はない。最小も最大も」**長さ自体は評価に無関係** |
| 見出しは h1→h2→h3 の順でないとダメ | 「Google Search の観点では順序が前後していても構わない」 |
| ドメイン名・URLにキーワードを入れる | 「ドメイン名やURLパスのキーワードは、パンくず表示以外にほとんど効果がない」 |
| E-E-A-T はランキング要因 | **明確に否定されている**（品質評価ガイドラインの概念であって、直接の要因ではない） |
| 重複コンテンツにペナルティがある | **ペナルティはない。** クロールが非効率になるだけ |

> ただし**アクセシビリティの観点では見出し順序は重要**（`0-core/accessibility.md`）。
> 「SEO 的には自由」と「作法として正しい」は別。**階層は守る。**

## Google が実際に求めていること

Google は要件を3層に分けている。

### 1. 技術要件（これがないと表示されない）
「実際にやることはごく少なく、たいていのサイトは意識せずに満たしている」

- Googlebot がブロックされていない（`robots.txt`）
- ページが機能する（HTTPステータス 200）
- インデックス可能なコンテンツがある

### 2. スパムポリシー（違反すると順位低下・削除）
キーワード詰め込み、隠しテキスト、無断コピー、不正なリダイレクトなど。
**普通に作っていれば触れない。**

### 3. ベストプラクティス（推奨）
以下はすべて「推奨」であって保証ではない。
Google 自身が「要件と推奨を全部満たしても、クロール・インデックス・表示されるとは限らない」と明記している。

## 実際にやること

### タイトル

**ページごとに固有で、簡潔で、内容を正確に表す。**

```html
<title>無料の業務診断 | Knacit</title>
```

- 会社名・地域など関連情報を入れてよい
- **全ページ同じタイトルにしない**（最も多い実害）
- 検索結果での表示は60字前後で切れるが、**文字数自体はランキングに無関係**

### ディスクリプション

**1〜2文の、ページ固有の要約。**

Google は実際のページ内容からスニペットを作るので、
**本文の書き方がそのまま検索結果の見え方になる。**

### 見出し

コンテンツを論理的に整理するために使う。
スクリーンリーダーにとって意味が通るようにする。

### リンク

- **アンカーテキストを説明的にする。**「こちら」「詳細」ではなく「料金プランを見る」
  → `ux-writing.md` と同じ原則。**SEOとUXがここで一致する**
- 信頼できない外部リンク・ユーザー投稿には `rel="nofollow"`
- 内容を裏付ける有用な外部リソースにはリンクしてよい

### 画像

- 鮮明で高品質な画像を、**関連するテキストの近く**に置く
- `alt` は「画像と本文の関係」を説明する
- 文脈に合った場所に置く

### URL 構造

```
○ /services/diagnosis
✕ /page?id=42
```

- **実際の単語を使う**、論理的な階層にする
- 話題の近いページをディレクトリでまとめる（クロール頻度の学習に役立つ）
- 重複は `canonical` かリダイレクトで整理する
- **サブドメイン vs サブディレクトリは「ビジネス的に妥当な方でよい」**（Google の見解）

### コンテンツ

- 固有で、よく書けていて、整理されていて、誤りがない
- **古くなった内容は更新するか削除する**
- ユーザーが使うであろう多様な言い回しを想定して、自然に書く
- 「人のための、役に立つ、信頼できる内容」

## BtoB サイトでの現実的な戦略

検索順位を直接操作する方法はない。**代わりに、勝てる場所を選ぶ。**

### 1. 指名検索と地域＋業種を取る

大手と「業務改善」で正面から戦っても勝てない。

```
✕ 業務改善            ← 競合が強すぎる
○ 山口県 業務改善 中小企業
○ 製造業 受発注 FAX 効率化
○ 会社名（指名検索）
```

**具体的で長い検索語のほうが、来る人の質も高い。**

### 2. 課題の言葉でページを作る

顧客が実際に検索する言葉は、サービス名ではなく**困りごと**。

```
サービス名で書く: 「伴走支援サービス」   ← 誰も検索しない
困りごとで書く:   「受発注のミスが減らない」「何から手をつけるべきか分からない」
```

②で集めた**顧客の言葉**（`process.md`）が、そのまま検索語になる。

### 3. FAQ を実際の質問で書く

商談で聞かれることは、検索でも聞かれている。
構造化データ `FAQPage` を入れると検索結果に出る可能性がある。

### 4. 会社情報を明示する

所在地・代表者名・設立年・事業内容。
BtoB の担当者は**本当に調べる**。信頼にも検索にも効く。

## 技術的な設定（一度やれば終わり）

- [ ] `robots.txt` — Googlebot をブロックしていないこと
- [ ] `sitemap.xml` — Search Console に登録
- [ ] `<link rel="canonical">` — 全ページ
- [ ] www あり/なしを片方に統一（リダイレクト）
- [ ] HTTPS。HTTP からリダイレクト
- [ ] 構造化データ `Organization`（＋該当すれば `FAQPage` / `BreadcrumbList`）
- [ ] `<html lang="ja">`
- [ ] 404 ページ
- [ ] Search Console に登録し、サイトマップを送信

→ 実装は `snippets/html/meta-head.html`

## OGP は SEO ではないが、流入に効く

検索エンジンは OGP を順位に使わない。
しかし **SNS やチャットで共有されたときの見え方**を決めるので、実質の流入経路として重要。

- `og:image` は **1200×630px**、絶対URL
- **実際に Slack や LINE に貼って確認する**（`launch-checklist.md`）

## やってはいけないこと

- キーワードを不自然に詰め込む（**スパムポリシー違反**）
- 他サイトの文章をコピーする
- 中身のないページを量産する
- 隠しテキスト・隠しリンク
- **「SEO対策」を謳う業者の、根拠のない施策を鵜呑みにする**
