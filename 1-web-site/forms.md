# フォーム（問い合わせ・申込）

**サイトで最も離脱が起きる場所。** ここまで読んで「やろう」と思った人を、
入力の面倒くささで失う。設計の投資対効果が最も高い箇所。

---

## 項目を減らす

**最大の改善は、常に項目を減らすこと。** デザインより先にこれをやる。

各項目について問う：
> **この情報がないと、次の一歩を踏み出せないか？**

踏み出せるなら**消す**。後で聞けばいい。

| よくある項目 | 本当に必要か |
|---|---|
| 会社名 | BtoBなら必要 |
| 氏名 | 必要 |
| メールアドレス | 必要 |
| **電話番号** | **多くの場合不要。「電話が来る」と思われて離脱の原因になる** |
| **部署・役職** | 不要。初回では聞かない |
| **住所** | 不要。物を送らないなら聞かない |
| **従業員数・業種** | 診断に必要なら聞く。営業リード分類のためなら消す |
| ご相談内容（自由記述） | 必要。ただし**必須にしない** |

**「営業部門が欲しいから」という理由の項目は、コンバージョンを削って情報を買っている。**
その交換レートが見合っているかを検討する。

---

## 分割するかどうか

| 項目数 | 形式 |
|---|---|
| 〜5項目 | **1ページ。分割しない** |
| 6〜15項目 | ステップ分割 ＋ 進捗表示 |
| 16項目〜 | そもそも減らせないか再検討 |

ステップ分割の効果は「1画面あたりの心理的負担を下げる」こと。
ただし**分割自体が離脱ポイントを増やす**ので、5項目以下では逆効果。

分割するなら：
- **進捗を必ず見せる**（「3ステップ中の1」）
- 前のステップに戻れる。**戻っても入力が消えない**
- 最初のステップを一番簡単にする（一度書き始めると完了率が上がる）

## 入力欄の設計

### ラベル

- **プレースホルダをラベル代わりにしない。** 入力を始めた瞬間に消えて、何の欄か分からなくなる
- ラベルは**入力欄の上**に置く（左横は視線移動が増え、モバイルで崩れる）
- ラベルはクリック可能に（`for` かラップ）

```html
<label for="email" class="block text-sm font-medium mb-2">
  メールアドレス <span class="text-red-600" aria-hidden="true">*</span>
</label>
<input id="email" name="email" type="email"
       autocomplete="email" inputmode="email" spellcheck="false"
       required
       placeholder="example@company.co.jp"
       class="w-full min-h-[48px] px-4 rounded-lg border border-neutral-300
              focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-rose-deep">
```

### 必須・任意の示し方

**任意項目の方が少ないなら「任意」と書く。必須の方が少ないなら「必須」と書く。**
`*` だけに頼らない（色覚・スクリーンリーダー）。

### type と inputmode

**モバイルで正しいキーボードが出るかどうかで、入力の苦痛が変わる。**

| 内容 | type | inputmode |
|---|---|---|
| メール | `email` | `email` |
| 電話 | `tel` | `tel` |
| 数値 | `text` | `numeric`（`type=number` はスピナーと丸めの事故がある） |
| URL | `url` | `url` |
| 郵便番号 | `text` | `numeric` |

### autocomplete

**必ず付ける。** ブラウザの自動入力が効くと入力時間が激減する。

```
name / email / tel / organization / postal-code / street-address
```

### 絶対にやらないこと

- ❌ **ペーストの禁止**（`onPaste` + `preventDefault`）。パスワードマネージャを壊す
- ❌ **半角のみ許可して全角を弾く**。ポステルの法則。**受け取ってから正規化する**
- ❌ 電話番号のハイフン強制
- ❌ 入力中の強制フォーマット（カーソルが飛ぶ）
- ❌ `maxlength` で切り捨てる（気づかず送信される）
- ❌ CAPTCHA を最初から見せる（不信感。不可視型か、送信時のみ）

## バリデーション

### タイミング

| 場面 | 挙動 |
|---|---|
| 入力中 | **エラーを出さない**（打ってる途中に赤くなるのは不快） |
| フォーカスを外した時 | その欄を検証する |
| 一度エラーになった欄 | 入力中に再検証して、直ったら即座にエラーを消す |
| 送信時 | 全体を検証。**最初のエラー欄にフォーカスを移す** |

### CSSだけでできる部分：`:user-invalid`

⚠️ 出典：[MDN — :user-invalid](https://developer.mozilla.org/en-US/docs/Web/CSS/:user-invalid)
（widely available・2023-11〜、2026-09確認。段階A、[`tech-stack.md`](tech-stack.md)）

**`:invalid` は使わない。** 表示直後・未入力の段階から赤くなり、上の表の「入力中はエラーを出さない」に反する。
`:user-invalid` は**ユーザーが一度操作した後**にだけマッチする。上表の「フォーカスを外した時」に近い挙動がCSSだけで手に入る。

```css
input:user-invalid { border-color: var(--border-danger); }

/* フォーム全体の送信ボタンの見た目を変える例（:has()と組み合わせ、css-architecture.md §3） */
form:has(:user-invalid) button[type="submit"] { opacity: 0.85; }
```

**メッセージの表示・`aria-describedby` の紐付けは、これでは代替できない。**
`:user-invalid` は見た目の同期だけ。`form-validate.js`（`snippets/js/`）のメッセージ制御と**二重に効かせない**
（両方が独立に赤枠をつけると、色は合っても消えるタイミングがズレることがある。境界線の色はCSS側、メッセージの出し分けはJS側、と役割を分ける）。

### エラーメッセージ

**何が問題か ＋ どう直すか**。両方書く。

| ✕ | ○ |
|---|---|
| 入力エラー | メールアドレスに「@」が含まれていません |
| 不正な値です | 電話番号は数字のみで入力してください |
| エラーが発生しました | 送信できませんでした。時間をおいて再度お試しください（解決しない場合は hello@example.com へ） |

表示位置は**該当フィールドのすぐ下**。ページ上部にまとめない。
色だけでなく**アイコンかテキスト**も添える。

`aria-describedby` でエラーを入力欄に紐付ける：

```html
<input id="email" aria-invalid="true" aria-describedby="email-error">
<p id="email-error" class="mt-2 text-sm text-red-700">
  メールアドレスに「@」が含まれていません
</p>
```

## 送信と完了

### 送信中

- **押した瞬間ではなく、リクエスト開始後に disabled にする**
- スピナーとテキストを出す：「送信中…」
- **二重送信を防ぐ**（サーバー側でも）

### 完了画面

**ピーク・エンドの法則。** ここが記憶に残る。手を抜かない。

書くこと：
1. **受け付けたことの明示**（「送信しました」だけで終わらせない）
2. **次に何が起きるか**（「3営業日以内に、ご入力のメールアドレスへ診断結果をお送りします」）
3. **届かない場合の対処**（「迷惑メールフォルダもご確認ください」）
4. 問い合わせ先

**自動返信メールを送る。** 「本当に送れたのか」の不安を消す最も確実な方法。

### 失敗したとき

- **入力内容を絶対に消さない**（最悪の体験）
- 何が起きたか、どうすればいいかを書く
- 代替手段を出す（メールアドレスを提示する）

## その他

- **未保存のまま離脱しようとしたら警告**（`beforeunload`）。ただし短いフォームでは過剰
- 長いフォームは `localStorage` に下書き保存すると強い
- `<form>` で囲み、`<button type="submit">` を使う。**Enter キーで送信できるように**
- モバイルで入力欄をタップした時に画面が拡大されないよう、**font-size は 16px 以上**
  （iOS Safari は 16px 未満の入力欄で自動ズームする。`user-scalable=no` で殺すのは禁止）
- `<textarea>` の自動伸長は `field-sizing: content` で書ける（⚠️ [MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/field-sizing)、
  newly available・2026-06〜と出たばかり。段階B・上乗せのみ、[`tech-stack.md`](tech-stack.md)）。
  `rows` 属性の指定と `resize` の挙動は残しておき、対応環境だけ上乗せする
