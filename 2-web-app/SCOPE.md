# 2-web-app — 扱う範囲

> 🔲 **未着手。** ここは SCOPE のみ。着手するときに、まずこの SCOPE を確定させてから中身を書く。

## 対象

**毎日使う、操作するための画面。**

- ダッシュボード
- 管理画面 / 業務システム
- SaaS のログイン後画面
- 内製ツール

## この対象の前提（`1-web-site` との決定的な違い）

| | LP・サイト | Web アプリ |
|---|---|---|
| ユーザー | 初めて来た他人 | **習熟していく同じ人** |
| 滞在 | 数十秒 | 数時間／毎日 |
| 離脱 | 1クリックで消える | **離脱できない**（業務だから） |
| 学習 | 期待できない | **期待できる**（ショートカット等が生きる） |
| 余白 | 広いほど良い | **広すぎると苦痛**（情報密度が価値） |
| 選択肢 | 絞る | **絞りすぎると回り道が増える** |
| 目的 | コンバージョン | **タスク完了までの時間と失敗率** |
| 成功指標 | 離脱率・CV率 | 作業時間・エラー率・サポート問い合わせ数 |

**この表が「混ぜない」理由そのもの。**
LP の作法（広い余白、大きなヒーロー、選択肢を1つに絞る）を管理画面に持ち込むと、
毎日使う人にとって苦痛な画面になる。

## ここに入れる予定のもの

- **情報密度の設計**（どこまで詰めていいか。density の切り替え）
- **データテーブル**：列設計、ソート、固定列、行選択、一括操作、ページネーション vs 無限スクロール
- **フィルタと検索**：ファセット、保存済みフィルタ、URL への状態反映
- **フォーム（アプリ内）**：インライン編集、自動保存、楽観的更新、競合の扱い
- **状態の設計**：ローディング（スケルトン vs スピナー）、空状態、エラー状態、部分失敗
- **ナビゲーション**：サイドバー、階層、パンくず、タブ、コマンドパレット
- **通知とフィードバック**：トースト、バナー、確認ダイアログ、取り消し（undo）
- **破壊的操作**：確認の作法、undo 猶予、ソフトデリート
- **権限とロール**による表示差分
- **キーボード操作**：ショートカット、フォーカス管理、モーダルのフォーカストラップ
- **大量データ**：仮想化、遅延読み込み、楽観的UI
- **現代的な Web アプリの実装傾向**（Linear / Vercel / Notion 系のUIが何をしているか、なぜか）

## ここに入れないもの

- LP のヒーロー、CTA、コンバージョン設計 → `1-web-site/`
- タッチジェスチャ、OS固有の作法 → `3-mobile/`
- コントラスト・タイポ・余白の数値基準 → `0-core/`
