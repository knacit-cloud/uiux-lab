# スクショを受け取ったとき

> ⚠️ 2026-11-20 作成。「読めない」の一覧は `references/input-methods.md` と同じ根拠（#17）。
> 「スクショ解釈の偏り」は**独自の観察**。出典なし。

## 読めること／読めないこと

| 読める（推定でよい） | **読めない**（聞く） |
|---|---|
| 並べ方（何が上、何が横） | **どこが気に入ったのか** |
| 一番目立つもの | 正確な色コード・文字サイズ・余白 |
| 密度（詰まっているか、余白が多いか） | ホバー・押したとき・空・エラーの状態 |
| 色の傾向（暗い・明るい・彩度） | スマホではどう組み替わるか |
| 書体の系統（明朝系・ゴシック系） | 本物の中身か、仮の文字か |
| 写真かイラストか | その会社がなぜそうしたか（業種・相手） |

**右の列を左の列の推定で埋めない。** 特に「どこが気に入ったか」は必ず聞く。

## スクショ解釈で AI が偏りやすいこと（独自）

| 偏り | 起きること | 対策 |
|---|---|---|
| 全体を均等に真似る | 本人が気に入ったのは見出しの組み方だけなのに、色まで真似る | 「どこを」を聞く |
| 見えている状態だけ作る | 通常状態しかない画面になる | 状態は必ず作る（`items.md` A5） |
| 見本の業種を持ち込む | SaaS の見本から、製造業のサイトに SaaS の言葉・図が入る | 見本の文言は使わない（`items.md` #10） |
| 見本のブランド色をそのまま使う | 他社と同じ色になる | 色は `4-brand` から取る |
| 画像の推定値を正確な値として扱う | 「#3B5BDB」などと断定して書く | 推定値は「推定」と書く。実測できるなら `metrics.js` |
| 1枚の見本に全部寄せる | 見本の劣化コピーになる | 見本が1枚なら「他にもありますか」と聞く。2〜3枚あると平均でなく**共通点**が取れる |

---

## 返答の型

```
このスクショから読めたこと（推定です）：
- 構成：〈例：左に大きな見出し、右に写真。その下に3列〉
- 一番目立つもの：〈例：見出し〉
- 密度：〈例：余白が多く、1画面の情報は少なめ〉
- 色の傾向：〈例：白背景、文字は濃い紺、アクセント1色〉
- 書体：〈例：ゴシック系、見出しは太め〉

読めなかったこと（ここを決めないと、AI の平均値で埋まります）：
1. このスクショの「どこ」を取り入れたいですか？（複数可）
   → [全体の雰囲気 / 並べ方 / 色 / 文字の組み方 / 写真の使い方 / 特定の部品（指してください）]
2. 逆に、真似したくない所はありますか？
   わからない場合：色・ロゴ・文章は真似しない
3. これは何のサイト（アプリ）ですか？ 作りたいものと業種は同じですか？
   わからない場合：見本の業種の言葉は使わない
4. 他にも気になる見本はありますか？
   （2〜3枚あると、偶然ではなく「共通して良い所」が取れます）
5. 〈items.md の必須項目のうち、まだ埋まっていないもの〉

（数値まで合わせたい場合は、そのサイトの URL をもらえれば実測します）
```

**URL がもらえるなら、スクショより URL を優先する。** 実測（`snippets/js/metrics.js`）できれば、
順位 B が S に近づく（`references/input-methods.md`）。
